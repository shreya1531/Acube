A Cube Design Studio — Project CMS

Site map / how the pages connect

  • index.html — public homepage. The Projects section is populated live from Supabase (published projects only) and links each card to project.html?id=.... Footer links to admin-login.html.
  • project.html — public project detail page, driven entirely by the id query param. Its own header links back to index.html and its in-page sections.
  • admin-login.html — sign-in gate. Redirects straight to admin.html if a session already exists; links back to index.html via "Back".
  • admin.html — dashboard (requires an authenticated Supabase session; redirects to admin-login.html otherwise). Lists projects with Edit and Delete, plus gallery thumbnail management. Links out to admin-add-project.html and admin-edit-project.html?id=....
  • admin-add-project.html / admin-edit-project.html — project forms (also session-gated); both return to admin.html on save or cancel.
  • setup.html — one-time Supabase SQL/setup reference; links to admin-login.html and index.html.
  • 404.html — fallback page for any URL that doesn't resolve (e.g. a deleted project link); links back to index.html. Point your host's custom-404 setting at this file.
  • robots.txt / sitemap.xml — crawling rules and the sitemap entry for search engines; admin/setup pages are disallowed and marked noindex.

Admin session security

  • Every admin page checks the Supabase session on load and redirects to admin-login.html if it's missing.
  • Logging in/out and the guard redirect use location.replace() (not location.href), so the dashboard doesn't stay in browser history after logout.
  • Admin pages also listen for the pageshow event and force a reload if the page was restored from the back/forward cache — so pressing Back after Logout re-checks the session instead of showing a stale cached dashboard.

SEO & mobile

  • index.html and project.html carry meta description, canonical link, Open Graph and Twitter Card tags, and robots: index, follow. project.html updates these dynamically (title, description, image, canonical URL) once the specific project loads.
  • Admin, login and setup pages are marked robots: noindex, nofollow so they don't show up in search results.
  • All pages share a small inline SVG favicon and a theme-color meta tag for mobile browser chrome.
  • robots.txt points crawlers at sitemap.xml and blocks the admin/setup pages. Replace the placeholder domain (https://www.acubedesignstudio.com) in robots.txt, sitemap.xml, and the canonical/og:url tags with your real production domain once deployed.
  • Every page already has a responsive viewport meta tag and mobile breakpoints (@media(max-width:900px/600px/520px)) — no changes needed there.

Deploying

  1. Run the SQL in setup.html against your Supabase project and create an admin user under Authentication → Users.
  2. Upload this whole folder as-is to any static host (Netlify, Vercel, GitHub Pages, S3, etc.) — every internal link is a relative path (index.html, project.html, admin.html …), so nothing needs rewriting for a subfolder or custom domain.
  3. Point your host's "custom 404" setting at 404.html if it supports one.
  4. Update the placeholder domain in robots.txt, sitemap.xml and the <meta>/<link> SEO tags in index.html/project.html to your real domain.

Content behaviour

  • Add/Edit project requires a Project Name; a Main Image is required for a new project.
  • Gallery images show immediate previews with an × button before saving/publishing.
  • Each project has a Project Date (month and year) chosen by the admin in the Add/Edit form. It is shown on the homepage cards and in the admin dashboard (e.g. "Sep 2026"). Run add_project_date.sql once in Supabase before using it.
  • The public Projects grid on the homepage is a fixed 3-per-row layout (2 on tablet, 1 on mobile); photos use object-fit: contain so they're never cropped, and each card shows the location, name, month, and short description.
  • Project detail gallery uses three images per row on desktop and one per row on mobile.
